# Deploy checklist: Study API

Use this file for each deploy of the Study API, and keep the filled-in copy in your own notes. The public repo keeps the blank template. Mark each item Done, Skipped (with the reason), or Failed (with what you did next).

Deployed by: ____________ Date: ____________ Commit: ____________

## 1. Before the deploy
- [ ] `pytest` passes for every test file in `tests/`, or each failing test is named and explained
- [ ] `docker build -t study-api .` finishes with no error, from `fastapi/study-api`
- [ ] `docker run` with a test key and a named volume answers `200` on `/health`, and the health status becomes `healthy` (lesson, section 7)
- [ ] `docker stop` finishes in about a second, and the exit code is 0
- [ ] No secret is in git: `git grep -n "STUDY_SECRET_KEY" -- ':!*.md'` returns only code that reads the variable
- [ ] No secret is in the image: `docker history --no-trunc study-api` shows no key
- [ ] `requirements.txt` lists every package with a version range

## 2. Platform settings (fill in once, check on each deploy)
- [ ] Service type: Docker web service. Region: ____________
- [ ] Dockerfile location and build folder: ____________ (the folder that holds the Dockerfile, or the repo root with the path set)
- [ ] Health check path: `/health`
- [ ] `STUDY_SECRET_KEY`: generated by the platform, at least 32 characters, never typed into a file
- [ ] `STUDY_ACCESS_TOKEN_MINUTES`: left at the default, or set to a value you chose on purpose
- [ ] `STUDY_AI_PROVIDER`: `stub`, or `gemini` with `STUDY_AI_API_KEY` stored as a secret in the platform, never in a file (module 13). `STUDY_AI_MODEL`: ____________
- [ ] `STUDY_RATE_LIMIT_PER_MINUTE`: left at 10, or a value you chose on purpose. With more than one instance, each one counts on its own (module 13, section 8)
- [ ] `STUDY_DATABASE_URL`: left at the image default only if a persistent disk is mounted at `/data`. Otherwise the database is a PostgreSQL URL (lesson, section 8)
- [ ] A persistent disk mounted at `/data`, if the platform offers one. Its size: ____
- [ ] `PORT`: set by the platform. Do not set it yourself

## 3. The deploy
- Build log: the image built with no error. Base image tag: ____________
- Start log: the migrations ran. Last revision applied: ____________
- Start log: uvicorn reports that it listens on `0.0.0.0` and on the port: ____________
- Deploy time (from the push to a live site): ____ minutes

## 4. Smoke tests (run on the live URL, over HTTPS)
- [ ] `http://` redirects to `https://`, or the platform serves HTTPS only
- [ ] `GET /health` returns `200` with `{"status": "ok"}`
- [ ] `GET /docs` loads
- [ ] `POST /auth/register` creates a user. Use a test username, not a real person's name
- [ ] `POST /auth/token` with that user returns an `access_token`
- [ ] `GET /me` with the token returns the user. Without a token it returns `401`
- [ ] A summary created with the token appears in `GET /me/summaries`
- [ ] `GET /summaries/999` returns `404` with the detail `summary not found`
- [ ] After a redeploy, the summary from before the redeploy is still there (only if a persistent disk is mounted)

## 5. Notes
Write down anything that did not go as planned, what you changed, and what you would check first next time.

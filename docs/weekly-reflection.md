# Weekly reflection

Spend five minutes at the end of each week, after the Day 6 review in [how-to-learn.md](how-to-learn.md). The daily wrap-up records a single day. The weekly reflection looks at the whole week: what you can do now, what still needs work, and what got in the way.

Copy the template below into your own notes. Keep the filled-in copy out of this repository. The repo is public, and the reflection is personal.

## How to run it

1. Set a five-minute timer.
2. Answer each question in one or two sentences. If an answer needs more, it belongs in your daily wrap-up notes.
3. Write one next step, and do it in the first Learn block of the next week.
4. At a checkpoint week, mark it honestly. The plan says to let a phase slip by up to one week rather than cram ([12-week plan](12-week-plan.md#if-you-fall-behind)).

## The template

Copy from the heading below to the end of the template.

### Week N reflection

**Date:** YYYY-MM-DD
**Modules finished this week:**
**Time:** learn __ h, build __ h, drill on __ of 5 days, wrap-up on __ of 6 days

**1. What I can do now without notes**
Name one thing you could explain or build today, in your own words.

**2. What still needs work**
Name the topic you would redo first, and say why.

**3. What got in the way**
Name one thing that cost you time or focus, and what you would change.

**4. Next week's first step**
One concrete action for the first Learn block.

**Checkpoint (weeks 4, 9 and 12 only)**
Write the checkpoint from the list below, then say whether it is met and what shows it: a passing test, a live link, or a commit.

## The three checkpoints

From the [12-week plan](12-week-plan.md):

- **End of week 4:** the Task Tracker CLI has tests that pass, and you can explain closures, generators, decorators and the MRO without notes.
- **End of week 9:** Gameya runs in production on Django, and you can explain why `select_related` fixes N+1 queries and how a migration works.
- **End of week 12:** two deployed projects, a README for each, and a blog-style "Django vs FastAPI, what I learned" note.

## An example

This is a filled-in week 2. Yours will look different.

- **Can do now:** write a function with default arguments, and call it with keyword arguments.
- **Needs work:** the order of `except`, `else` and `finally`. I mixed up when `finally` runs.
- **Got in the way:** an install failed, and the Build block shrank to 30 minutes. Next time I will check the virtual environment before the Build block starts.
- **Next step:** redo the Error handling drill from memory in the first Learn block.

Judge the week by what you can explain without notes. Hours help with planning, but they do not show what you learned.
